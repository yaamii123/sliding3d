# 3D Sliding Puzzle

A browser game that extends the classic 15-puzzle into a genuine cubic grid. Numbered cubes occupy an N×N×N lattice with a single empty cell. Pieces slide along **X**, **Y**, and **Z** — the third dimension is part of the rules, not just the camera.

Default size is **3×3×3** (26 cubes + 1 gap). 2×2×2, 4×4×4, and 5×5×5 are also playable.

## How the 3D puzzle works

The board is a cubic grid. One cell is empty. A cube may slide if it shares an axis with the empty cell — the same X line, Y line, or Z line:

- `dy = 0`, `dz = 0`, and `dx ≠ 0`, or
- `dx = 0`, `dz = 0`, and `dy ≠ 0`, or
- `dx = 0`, `dy = 0`, and `dz ≠ 0`

Clicking a cube on that line shifts every cube between it and the gap one step toward the empty cell, so several pieces can move at once. Diagonals are illegal. Orbit the camera to see faces that would otherwise be hidden — you often need a different viewpoint to notice a legal Z-axis slide.

The solved configuration is deterministic: tiles `1 … N³−1` in index order, empty in the last cell. From the default camera that means numbers run **right**, then **down**, then **toward you** — the same reading order as a classic 15-puzzle, with layers stacked back to front. A tagged **1** marks the top-left-back home corner; a gold frame marks where the gap belongs (bottom-right-front). Cubes glow when they sit in their home cell, and each cube’s color encodes its home position as a 3D gradient.

Scrambles are generated by walking randomly from the solved state with the same line-slide rule the player uses: any cube on the empty cell's axis, not only the adjacent ones. That mixes 3×3×3 and larger cubes far more than single-step walks. Every deal is solvable. The walker also refuses to immediately undo the previous step, so the scramble does not collapse into a short back-and-forth.

Each size has a fixed scramble length:

| Size | Scramble moves |
| --- | --- |
| 2×2×2 | 30 |
| 3×3×3 | 180 |
| 4×4×4 | 450 |
| 5×5×5 | 1500 |

## Install

```bash
npm install
```

## Run

```bash
npm run dev
```

Then open the local URL printed by Vite (typically `http://localhost:5173`).

## Build

```bash
npm run build
```

Preview the production bundle with `npm run preview`.

Logic tests (no browser required):

```bash
npm test
```

There is no backend. Everything runs in the client, including scramble generation, undo, best times (`localStorage`), and the optional solver.

## Controls

| Input | Action |
| --- | --- |
| Click / tap a cube | Slide it if it shares an axis with the empty cell |
| Left drag | Orbit camera |
| Right drag | Pan |
| Wheel / pinch | Zoom |
| `N` | New puzzle |
| `R` | Reset to this scramble’s starting position |
| `U` | Undo |
| `Space` | New scramble |
| `C` | Reset camera |
| `X` | Spread / pack cubes (inner layers) |
| `H` | Hint |
| `S` | Solve |
| Arrow keys | Nudge camera orbit |

## Puzzle mechanics

- **Timer** starts on the first player move, uses `performance.now()`, pauses when idle (including after undoing back to zero moves), and stops on solve.
- **Undo** restores the previous logical state and animates the cube back. It is disabled after a solve so the completion record stays intact.
- **Reset** returns to the scramble you started with, not a brand-new deal.
- **Hint** highlights a useful cube. On 2×2×2 / short 3×3×3 positions it uses a search; otherwise it picks a legal move that reduces 3D Manhattan distance.
- **Solve** on an untouched scramble simply plays the scramble backwards (works for every size, including 4×4×4 and 5×5×5). After you have moved, 2×2×2 is solved with BFS and 3×3×3 with budgeted A*. 4×4×4 and 5×5×5 search is disabled so the tab cannot freeze — use Undo back to the start, or Hint.

Using Solve disqualifies that run from **Best Times**. Hints do not.

Cube colors can be switched from the bar: **Gradient** encodes home as a 3D tint (right / down / toward you), **Depth** uses one color per back-to-front layer, **Height** one color per floor, and **Stone** a single color so you read the digits.

On 4×4×4 and 5×5×5 the packed cube hides inner cells. Live cubes get a gold rim; cubes off the empty cell’s axes stay visible but do not move. **Spread** (`X`) pulls every cell apart so you can see and click cubes that would otherwise sit behind a neighbor on the same line. The **Layers** panel (right side on desktop, a **Layers** button on small screens) shows the same cube as 2D slices from back to front. Gold-outlined cells are legal slides — tap them to move without hunting through the 3D view. A **Goal** tab shows the solved layout.

## Architecture

Puzzle logic, Three.js rendering, and HUD are separate:

```text
src/
  game/          Pure state: moves, scramble, undo, solver, validation
  hooks/         React bindings for the game, timer, keyboard, records
  components/    R3F scene + DOM UI
  types/         Shared types
  utils/         Coordinates, RNG, formatting, textures, persistence
```

`src/game` does not import Three.js or React. Tests target that layer so scramble solvability, 3-axis movement, and undo can be proven without a GPU.

Rendering keeps one mesh per numbered cube (keyed by piece id) and interpolates world position when the logical cell changes. The empty cell is a faint cage, not a numbered cube.
